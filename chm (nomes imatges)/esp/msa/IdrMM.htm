IdrMM: Importación y exportación entre formatos ráster de Idrisi y MiraMon

Este módulo transforma archivos ráster entre MiraMon e Idrisi-32.

Los tipos de transformaciones inplementadas son:

  • Exportación de una banda de cualquier formato IMG de MiraMon a formato RST de Idrisi-32.
  • Importación de Idrisi-32 en formato RST monobanda a IMG de MiraMon.
  • Exportación de JPEG georreferenciados (J.rel) de MiraMon a un archivo RST de tres bandas RGB de Idrisi-32.

Ambos archivos, IMG y RST, son binarios, pero MiraMon acepta más tipos que Idrisi-32. Idrisi-32 soporta los tipos byte, integer y real, mientras que MiraMon acepta además, los tipos bit y long y las correspondientes compresiones RLE (byte-RLE, integer-RLE...). Como Idrisi-32 no soporta el tipo long se puede decidir que los datos del archivo de Idrisi-32 transformado sean integer o real mediante un parámetro optativo. En el caso de una exportación de un ráster MiraMon de tipo long a Idrisi-32 de tipo integer, el parámetro optativo a utilizar es /LONG_SHORT y en el caso de una exportación a Idrisi-32 de tipo real el parámetro optativo a utilizar es /LONG_REAL. Por defecto (si no se especifica el parámetro optativo) el módulo aplica /LONG_REAL.

En el caso de una transformación de MiraMon a Idrisi-32 con el parámetro optativo /LONG_SHORT la aplicación satura los valores del ráster origen superiores a 32767 o inferiores a -32768. La saturación se realiza siguiendo el siguiente protocolo:

  • Si el ráster origen contiene valores NODATA superiores a 32766 o inferiores a -32767, la aplicación definirá el valor NODATA en 32767 en el primer caso y en -32768 en el segundo. El resto de valores del ráster origen superiores a 32766 o inferiores a -32767 se asignan a 32766 o a -32767 respectivamente.
  • Si el ráster origen no contiene valores NODATA, los valores superiores a 32766 o inferiores a -32767 se asignan a 32767 o a -32768, respectivamente.

Cabe destacar que este módulo no realiza exportaciones de archivos con datos de tipo bit; para ello deben transformarse los datos a tipo byte con la aplicación IMGIMG y posteriomente exportar a RST. Tampoco importa a formato MiraMon archivos RST de 24 bits (composiciones de tres bandas) de Idrisi-32; en este caso se aconseja usar un formato TIFF (georreferenciado como GeoTiff) como intermediario y entonces usar el módulo TIFIMG para obtener el correspondiente IMG de 24 bits.

Sobre los archivos ráster de Idrisi-16 cabe indicar que tienen el mismo formato que los archivos de MiraMon; por tanto todos los archivos ráster de Idrisi-16 RST que sean binarios y no comprimidos se pueden leer directamente con MiraMon con la opción "Archivo | Abrir ráster". Aún así, existen algunas situaciones especiales que se detallan a continuación:

De Idrisi-16 a MiraMon:

  • Si el archivo es ASCII o comprimido ("packed") se debe convertir a binario no comprimido con la utilidad CONVERT de Idrisi-16 (para los ASCII tambien se puede utilizar, desde MiraMon, "Archivo | Importar | ASCII->IMG").
  • Si se desea ampliar el modelo de metadatos del archivo DOC de Idrisi-16, debe hacerse con GeM+, con la posibilidad de mantener los dos formatos (DOC i REL).

De MiraMon a Idrisi-16:

  • Si el archivo ráster de MiraMon es byte y RLE se debe verificar que no sea extracomprimido y que no sea indexado (IMGIMG) y cambiar la documentación que figura en el DOC ya que MiraMon especifica que los datos están comprimidos (RLE) en el mismo campo tipo datos (p.ex. byte-RLE) e Idrisi-16 escribe el RLE en otro campo.
  • En el caso de que el archivo ráster de MiraMon tenga metadatos en formato REL, debe utilizarse el Gestor Universal de Metadatos Geoespaciales (GeM+) para transformarlos a formato DOC.
  • En el caso de que el archivo ráster de MiraMon sea de tipo long o long-RLE, se deben tener en cuenta las consideraciones de las transformciones entre MiraMon e Idrisi-32.
  • En el caso de que el archivo ráster de MiraMon sea de tipo short o long con categorías (con valores superiores a 255), no se puede transformar a Idrisi-16.
Sintaxis:
IdrMM 1/2/3 ArchivoOrigen ArchivoDestino [ParámetroOptativo]
  • Opción 1: Exportación de MiraMon (ArchivoOrigen ) a Idrisi-32 (FitxerDestino). Los parámetros opcionales de esta opción son:
    • /LONG_SHORT realiza una exportación de datos origen tipo long a datos destino tipo integer.
    • /LONG_REAL realiza una exportación de datos origen tipo long a datos destino tipo real.
  • Opción 2: Importación desde Idrisi-32 (ArchivoOrigen) a MiraMon (ArchivoDestino). Este caso no tiene parámetros opcionales.
  • Opción 3: Exportación de imágenes JPEG (ArchivoOrigen) a archivos RGB de Idrisi-32 (ArchivoDestino). Si la imagen origen está georreferenciada (J.rel), se genera un RST georreferenciado. Este caso no tiene parámetros opcionales.
