VECPNT: Conversion between VEC (point) files and PNT files

This application performs the conversion from point files in VEC format (ASCII) to point files in PNT format (binary and structured), and vice versa. It can also simplify a PNT file by collapsing such points inside a given distance.

The VEC format is partially compatible with the Idrisi VEC files, but it admits the "integer" attributes to be of "long" type (it is, in the range [-2147483648, 2147483647] instead of [-32768, 32767]), it expresses the coordinates in double precision and supports attributes of type "string". All the Idrisi VEC ASCII formats are compatible with VECPNT.

PNT format is a structured format that allows explicit topological relationships between points (in this case, control of spatial uniqueness), but can also be used without explicit topological relationships to store files in a more efficient format (faster management) and with much more sophisticated properties (multiple attributes per entity, multiple records [multiple record] per entity, full metadata, default symbolization, etc). Indeed, a PNT file is a binary file that is associated with a T.dbf file with its attributes and a T.rel file with complete metadata (field descriptors, relationships to other tables, etc), default symbolization, and other information of interest.

In options 1 and 3, if 'n' points are nearer than the defined tolerance, they are joined in one point and the application generates as many records as different attributes exist [thus generating multiple register]. When converting VEC to PNT, the order of the points in a PNT file is not the same than the original VEC file. Instead, they are sorted first by X coordinate and then by Y coordinate. This order is not inherent to the format, but a particularity of the application that orders them to accelerate the topological structuring if requested.

Syntax:
VECPNT 1 VecFile PntFile Tolerance [/AJUST_ENV] [FieldDescriptor [FieldName]]
VECPNT 2 PntFile VecFile Precision [/AJUST_ENV] [OptionalParam]
VECPNT 3 PntFile PntFile Tolerance [/AJUST_ENV] [/MULTIREG]
  • Option
    • 1: Transforms VEC files to PNT files
    • 2: Transforms PNT files to VEC files
    • 3: Transforms PNT files to PNT files (simplify)
  • PntFile is the name of the topologically-structured point file
  • VecFile is the name of the point file of VEC type (the names of PntFile and VecFile can be the same since their extension is different).
  • FieldDescriptor is a text string (between quotes if it has blank spaces) which describes the Attribute field (maximum 40 characters); empty by default.
  • FieldName is a text string (10 characters maximum) which will be used as the field name in the database that will be created; by default it will be ATR_VEC_? where ? is L, F or C depending on whether the attribute is an integer, a real or a text string.
  • Precision is a number which indicates the number of decimal places which will be printed in the coordinates of the output file in a VEC file.
  • /AJUST_ENV adjust the bounding documented in the layer metadata to the minimum rectangle.
  • /MULTIREG all registers of collapsed points remain in the final database (if param is not specified, only registers of final points remain)
  • [OptionalParam] Optional parameters (Option 2 only):
    • /TAULA= and /CAMP= set database field to be exported in a VEC format. To learn more about the values of these parameters follow the considerations in general syntax.
    • /SI_EN_BLANC= sets the VEC exportation behavior when the attribute do not exist in the database (blank field). Can be "CONSTANT" to write a constant value, "ID_GRAFIC" to write graphic identificator or "IGNORAR" to ignore vectors without attribute (default value).
    • /ATRIBUT_CONSTANT= sets a constant that is going to be write as object attribute when exporting to VEC format. If it is used in combination with /TAULA=, /CAMP= and /SI_EN_BLANC=CONSTANT is the attribute that is going to be used when there is no data (blank field).
      If /TAULA=, /CAMP= or /ATRIBUT_CONSTANT= is not indicated the VEC format exportation is done using graphic identificator as attribut.
    • /ALCADA= sets which of the possible heights are used in the VEC. To learn more about the values of this parameter follow the consiterations in general syntax.
